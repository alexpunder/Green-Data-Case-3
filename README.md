# Разработка интеллектуальной системы генерации и аудита безопасности SQL-запросов

## Цель

Создать MVP многоагентной системы, которая по текстовому описанию задачи автоматически генерирует SQL-запросы для PostgreSQL, проверяет их на уязвимости безопасности и итеративно исправляет до получения одобренного результата — с полным логом аудита для пользователя.

## Заказчик и проверяющий

GreenData — российский разработчик low-code-платформы для создания корпоративных ИТ-систем (CRM, ERP, ITSM и др.), лидер рейтинга российских low-code-платформ 2025 года по версии «Сколково» и TAdviser.

## О проекте

- Находит релевантные таблицы в схеме БД
- Генерирует SQL-запрос с помощью локальной LLM
- Проверяет запрос на уязвимости (SQL injection, DROP, отсутствие LIMIT и др.)
- Итеративно исправляет ошибки на основе feedback от аудитора
- Логирует все шаги с метриками (токены, время, риск)

**Ключевая особенность** — полная локальная работа без API-ключей и бесплатно

                                 │

└─────────────────────────────────────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────┐
│                      Результат (SQL + лог)                      │

| Компонент | Назначение |
|-----------|------------|
| **Streamlit UI** | Чат-интерфейс с историей |
| **Qdrant** | Векторный поиск таблиц |
| **SQLGenerator** | Генерация SQL (Ollama + qwen2.5-coder) |
| **SecurityAuditor** | Проверка уязвимостей |
| **IterationController** | Feedback-цикл (до 5 итераций) |
| **Результат** | SQL + лог аудита + метрики |

## Быстрый старт

### Требования

- Python 3.12+
- [Ollama](https://ollama.ai/) (с GPU для быстрой работы)
- 8-16 GB RAM (для 7B модели)
- NVIDIA GPU (опционально, но значительно ускоряет)

### Установка

```bash
# 1. Клонируем репозиторий
git clone https://github.com/alexpunder/Green-Data-Case-3.git
cd Green-Data-Case-3

# 2. Устанавливаем зависимости (через uv)
pip install uv
uv sync

# 3. Устанавливаем Ollama и скачиваем модель
curl -fsSL https://ollama.com/install.sh | sh
ollama pull qwen2.5-coder:7b

# 4. Запускаем Qdrant и Postgres (локально)
docker compose up -d

# 5. Запускаем приложение
uv run streamlit run src/app.py
```

## Краткая сводка по MVP

### Что уже работает

- Парсинг схемы БД из SQL-дампа
- Векторный поиск таблиц (Qdrant)
- Генерация SQL (Ollama + qwen2.5-coder)
- Аудит безопасности (13+ классов)
- Итеративное улучшение
- Логирование и метрики
- Streamlit UI

### Что можно улучшить

1. Поиск таблиц — RAG не идеален для сложной схемы:
- использовать гибридный поиск (keyword + vector)
- использовать заранее прописанные шаблоны для частых запросов
- ИЛИ улучшить описание самих таблиц и полей для лучшего поиска

2. Модель — локальная 7B иногда путает таблицы (хотя если RAG передал нужные в контекст, то все отлично работает):
- перейти на более "умную" и полную модель
- дообученить 7B модели на нужной схеме

3. Аудитор — добавить проверку:
- существования колонок в таблицах
- бизнес-правил (например, "нельзя удалять счета с проводками")

4. Тесты — переписать на гибкое семантическое сравнение (AST или ключевые компоненты)
